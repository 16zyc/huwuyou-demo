# 最终 UI 提升方案

> 原则：**不重新设计，不推翻现有体系**。在当前已完成的设计系统与品牌基因上做"收敛、补缺、提质"。
> 每项给出：问题 → 原因 → 优化目标 → 具体方案 → 实现建议 → 优先级。

## 1. 当前优点（必须保留）

1. **品牌基因清晰**：#3b6cb5 蓝系 + slate 灰阶 + Noto Serif SC 衬线标题，医疗可信感成立。
2. **Design Token 完整**：spacing/type/shadow/radius/motion/glass 六类 token 已落地，`--warm` 已修复，reduced-motion 全局化。
3. **玻璃材质开始应用**：TabBar、后台顶栏、AI 面板三处 backdrop-filter 均带 @supports 降级。
4. **方向性动效达标**：页面转场（slideIn 350ms ease-out）、底部抽屉、AI 面板入场符合 Apple Motion 基本要求。
5. **组件基础扎实**：状态徽章公式、focus 光环、Chip 选择器、确认卡多步流程都规范。
6. **价格/日期/陪诊师三大业务一致性已修复**，视觉系统可以专注"质感"问题。

## 3. 配色优化方案

### 3-1 消除 Banner 紫色渐变

- **问题**：首页 Banner `#667eea→#764ba2`，非品牌色。
- **原因**：早期设计遗留，未随品牌收敛。
- **目标**：Banner 回到品牌蓝渐变，或改为浅蓝底深蓝字的"轻量信息条"。
- **方案**：`linear-gradient(135deg, var(--accent), var(--accent-deep))`，副文案白色 0.9 透明度。
- **实现**：style.css:405 `.ph-banner-placeholder`。
- **优先级**：P1（品牌一致，改动一行）。

### 3-2 服务卡从"四色"收敛为"蓝系层次"

- **问题**：四服务卡 c1 蓝/c2 绿/c3 橙/c4 黄（style.css `.ph-svc-tile.c1-c4`），颜色杂音。
- **原因**：用颜色区分服务，但绿/橙是状态色，混用降低可信感。
- **目标**：四卡统一蓝系 tint，用图标/编号区分服务。
- **方案**：c1-c4 背景统一为 `rgba(59,108,181,0.06-0.10)` 阶梯；图标底色同蓝系；hover 加深 0.02。
- **实现**：style.css `.ph-svc-tile.c1~c4` 与 patient.js 注入同款（两处同步改）。
- **优先级**：P2。

### 3-3 恢复琥珀的差异化职责

- **问题**：琥珀 token 存在但首页未使用，AI 入口与人工入口同蓝。
- **目标**：AI 智能下单 = 琥珀主题；人工下单 = 品牌蓝主题，形成品牌记忆。
- **方案**：AI banner 用 `linear-gradient(135deg, var(--accent-amber), #a87a22)`（琥珀深阶需补 token）；琥珀仅在 AI 入口、"推荐"标签使用。
- **实现**：patient.js 首页双入口内联样式。
- **优先级**：P2。

### 3-4 建立"蓝阶"体系（浅底→主蓝→深蓝）

- **问题**：蓝的使用"全或无"，无层次。
- **目标**：3 级蓝阶用于面板/主操作/强调文字。
- **方案**：新增 `--accent-50: rgba(59,108,181,0.05)`、`--accent-100: rgba(59,108,181,0.10)`、`--accent-700: #254d86`（深蓝深阶）；确认卡/步骤条/统计强调字分别使用。
- **实现**：style.css :root + 相关组件。
- **优先级**：P2。

## 4. 动画优化方案

### 4-1 全局可点卡片按压态（P1）

- **问题**：服务卡/订单卡/医院卡点击无按压反馈。
- **方案**：新增 `.pressable { transition: transform var(--dur-fast) var(--ease-standard), box-shadow var(--dur-fast); } .pressable:active { transform: scale(0.98); }`，页面卡片统一加类。
- **实现**：style.css + patient.js 渲染模板批量加类。

### 4-2 订单状态高亮（P2）

- **问题**：状态徽章/订单卡状态变化瞬时跳变。
- **方案**：状态变化时给订单卡加 `flash` 类（accent-bg 600ms 淡出），完成时绿色微闪。
- **实现**：workflow.js renderProgress / patient.js 订单渲染。

### 4-3 消息/步骤过渡（P2）

- **问题**：AI 对话整体重绘。
- **方案**：新消息 `.msg-enter`（225ms 淡入）；步骤条当前项 200ms 背景淡变。
- **实现**：workflow.js renderAiConversation + workflow.css。

### 4-4 统一 loading 反馈（P2）

- **问题**：无骨架屏；表单提交按钮无 loading。
- **方案**：`.btn.loading`（spinner 12px 600ms 旋转 + 文案"提交中…"）；列表加载可暂用 shimmer（P3）。
- **实现**：style.css + patient.js `_submitBooking`。

## 6. 组件优化方案

### 6-1 卡片统一规则（P2）

- 浅灰底上的卡片：**去边框、用双层 shadow-sm**。
- 白底上的分区：**hairline 边框、无阴影**。
- 实现：style.css 卡片选择器统一替换；patient.js 注入样式同步。

### 6-2 按钮体系补齐（P2）

- 主按钮高度统一 44px（`.btn` 当前约 41px）。
- 补 `.btn-amber`（AI 入口）、`.btn.loading`。
- active 反馈统一 `scale(0.98)` 150ms。

### 6-3 表格与后台（P2/P3）

- 表格行 hover 统一 `--bg-hover`；金额/统计数字 `tabular-nums` 右对齐。
- KPI 卡"重点数字"用 24px/700 + 深蓝，环比小标签绿升红降。

### 6-4 表单（P2）

- 提交按钮 loading 态；成功 toast 后 600ms 卡片高亮。
- 错误字段红框 + 12px 错误文案（当前仅 toast）。
