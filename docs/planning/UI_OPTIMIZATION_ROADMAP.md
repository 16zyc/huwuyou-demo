# UI 优化路线图（逐页面）

> 依据：CURRENT_UI_ANALYSIS.md（现状）+ APPLE_DESIGN_REFERENCE.md（依据）+ UI_DESIGN_SYSTEM.md（规范）。
> 优先级：P0 = 影响核心流程/品牌可信；P1 = 明显提升体验；P2 = 打磨细节。
> 所有调整必须遵守 UI_DESIGN_SYSTEM.md，不得改变品牌色。

## A. 患者端

### A1. 首页

**当前问题**

- "人工下单 / AI下单"入口存在但视觉层级与信息展示不足，未突出"两种下单方式"的产品卖点。
- 服务入口与医院介绍区在同一页面，空间挤压，后续新增内容无位置。

**优化目标**

保留并强化"人工下单 / AI下单"双入口；服务四卡两排；医院介绍区独立成卡且可扩展。

**视觉调整**

- 品牌区：顶部"护无忧"标识（衬线 24px）+ 一句品牌语，浅灰底上留白 24px。
- 双入口：两张大卡片并排（各 50%），人工下单 = 主蓝主题，AI下单 = 琥珀主题；卡片内图标 28px + 标题 17px + 说明 13px。
- 服务入口：四张服务卡 2×2 网格（间距 12px），卡片图标 + 名称 + 一句话说明。
- 医院介绍：独立白卡（标题 17px 无衬线 + 内容 13px），底部预留"更多内容"扩展位。

**交互调整**

- 双入口与服务卡均为可点卡片：按压 scale(0.98) 150ms。
- 服务卡点击进入二级目录；双入口点击进入对应下单流程（人工=表单，AI=对话）。

**动画调整**

- 页面进入：fade + 轻微上移（350ms ease-out）。
- 区块依次淡入（间隔 40ms，仅首次加载）。

**组件调整**

- 新增 `.entry-card`、`.service-card`、`.home-hospital-card`。

**优先级**：P0

---

### A2. 服务二级目录页

**当前问题**

- 四个服务排布空间不足，下方无法扩展。
- 与首页服务区视觉重复，层级感弱。

**优化目标**

四服务两排稳定布局；预留扩展位；明确"二级目录"层级。

**视觉调整**

- 页面主标题（衬线 20px）+ 返回按钮。
- 服务列表统一两列卡片（或四宫格），卡片高度一致、文字两行截断。
- 列表底部预留"更多服务敬请期待"占位卡（虚线框，后续可替换为真实服务）。

**交互/动画**

- 卡片按压反馈；进入服务详情页时页面右侧滑入。

**优先级**：P0（与需求"四服务两排 + 扩展空间"直接相关）

---

### A3. 服务详情 / 立即预约（核心流程页）

**当前问题（结合产品需求）**

- 现流程为"进入服务 → 立即预约 → 陪诊师选择"，与目标流程不符。
- 目标流程：进入服务 → 立即预约 → 填写患者信息 → 提交订单 → 我的订单查进展 → 后台配陪诊师 → 患者查看陪诊师信息。
- 当前表单无错误态/成功态/时间范围选择。

**优化目标**

按目标流程重构预约页为"信息填写页"，陪诊师选择整体移除。

**视觉调整**

- 表单分区卡片：①患者基本信息（姓名/手机/性别/年龄）②就诊需求（就诊医院、科室、就诊时间）③诊前咨询（病情简述 textarea + 可选补充项）。
- 时间选择用 Chip 组：`尽快` / `1-3 天` / `一周内`（单选，选中态主色），并注明"由平台为您协调具体时间"。
- 诊前咨询区加辅助说明：帮助管理员匹配合适的陪诊师。
- 底部固定主按钮"提交预约"（全宽 48px，含 safe-area）。

**交互调整**

- 提交前整组校验：错误字段红框 + 顶部错误条。
- 提交成功：按钮变"已提交"（禁用）+ 成功状态提示。

**动画调整**

- 提交中：按钮 loading（spinner）。
- 提交成功：轻微成功反馈（600ms 主色高亮闪过）后跳转订单页。

**组件调整**

- 新增 `.chip`、`.form-section`、`.input-error`、`.bottom-action-bar`。

**优先级**：P0（产品核心流程）

---

### A4. 我的订单页

**当前问题**

- 订单状态展示以文字/徽章为主，用户难以感知"提交→审核→匹配陪诊师→服务→完成"的进展。

**优化目标**

订单状态可视化、等待感可预期、匹配后展示陪诊师信息。

**视觉调整**

- 订单卡片：顶部状态徽章 + 服务名 + 时间；中部步骤时间线（5 步：已提交→待审核→匹配中→已匹配→服务完成）。
- 未匹配时显示"陪诊师匹配中，平台将尽快为您安排"（不可见任何陪诊师信息）。
- 已匹配时显示陪诊师卡：姓名、照片占位、专业方向、联系电话（主色文字按钮，仅此阶段可见）。
- 待办/取消按钮用次按钮样式。

**交互/动画**

- 状态变化时高亮闪过（600ms）；时间线当前步骤主色。

**优先级**：P0

---

### A5. 用户中心（我的）

**当前问题**

- 功能入口排列简单，缺少层级与品牌感。

**优化目标**

简洁的个人中心：用户卡片 + 核心入口 + 设置。

**视觉调整**

- 顶部用户卡：头像占位 + 姓名/手机号 + 编辑入口。
- 入口列表分组：订单中心（我的订单）、咨询（AI 咨询）、收藏医院、帮助与反馈、设置。
- 分组列表用浅灰底卡片分组（借鉴系统设置分组，但保持卡片式，不做 iOS 全屏分组表）。

**优先级**：P1

---

### A6. AI 咨询页

**当前问题**

- 聊天界面基本可用，但气泡/输入栏质感与状态反馈一般。

**优化目标**

清晰安静的双人对话体验。

**视觉/交互调整**

- 用户气泡：主蓝底白字、右对齐、圆角 16px（单边 4px）。
- AI 气泡：白底 + 浅描边、左对齐。
- 输入栏：毛玻璃底（glass-bar）+ 44px 输入框 + 发送按钮（44px 热区）。
- 打字中：三点跳动指示器（仅 AI 侧，400ms 循环）。

**优先级**：P1

---

### A7. 医院列表页

**当前问题**

- 列表信息密度与卡片质感一般。

**优化目标**

医院卡片：名称（15px/600）+ 等级徽章 + 科室标签 + 地址（13px 灰）。

**优先级**：P2

---

## B. 管理后台

### B1. 后台登录页

**优化目标**

居中卡片式登录（max-width 400px），品牌区 + 表单 + 主按钮（44px），背景浅灰。错误提示：字段红框 + 顶部错误条。

**优先级**：P1

---

### B2. 运营工作台（数据总览）

**当前问题**

- 统计卡与图表已存在，但视觉密度与层级不足（阴影弱、无重点数据强调）。

**优化目标**

高信息密度、数据视觉化、一屏可扫读。

**视觉调整**

- KPI 卡片：数值用 24px/700 tabular-nums + 环比小标签（绿升/红降）+ 图标。
- 图表卡片：统一标题栏（16px/600）+ 说明（13px 灰）；图表用主蓝/琥珀双色系。
- 卡片 hover：translateY(-1px) + md 阴影。

**优先级**：P0（后台第一屏）

---

### B3. 患者档案

**优化目标**

筛选条（搜索 + 状态筛选）统一组件化；列表行 hover 高亮；关键字段（病情等级）用徽章。

**优先级**：P1

---

### B4. 需求处理（订单匹配）

**当前问题（结合产品需求）**

- 该模块是"管理员配置陪诊师"的核心落点，当前已存在，但匹配操作的引导与状态反馈可强化。

**优化目标**

订单详情抽屉：左列患者信息 + 诊前咨询摘要，右列陪诊师候选列表（可筛选），底部"确认匹配"主按钮。匹配成功后订单状态自动推进，患者端可见陪诊师信息。

**优先级**：P0（核心流程闭环）

---

### B5. 陪诊师管理

**优化目标**

列表卡（头像/姓名/专业/状态徽章）+ 详情弹窗（资料、服务记录、评价）。新增/编辑用表单弹窗，统一输入规范。

**优先级**：P0

---

### B6. 医院审批

**优化目标**

待审批列表 + 审批弹窗（医院信息 + 通过/驳回操作）。驳回必须有原因输入。

**优先级**：P1

---

### B7. 服务跟踪

**优化目标**

进行中订单时间线（提交→匹配→服务中→完成）+ 位置状态区（占位）。状态切换高亮。

**优先级**：P1

---

### B8. 服务收费（价格管理）

**优化目标**

套餐表格：服务名/定价/生效时间/状态 + 行内编辑（弹窗）。金额 tabular-nums 右对齐。

**优先级**：P1

---

### B9. 评价反馈

**优化目标**

评价卡片分级（好评/中评/差评徽章）+ 差评自动标记回访状态（状态徽章 + 处理按钮）。

**优先级**：P2

---

### B10. 系统设置

**优化目标**

分组设置表单（基础/价格/AI/审计），开关组件统一（主色开关），保存按钮固定页脚。

**优先级**：P2

---

### B11. 未来页面（数据统计 / 内容管理）

**设计要求**

- 数据统计：KPI 卡 + 趋势图（主蓝）+ 导出按钮；遵循 B2 规范。
- 内容管理（信息发布）：列表 + 草稿/已发布状态徽章 + 编辑器弹窗；遵循 B3-B5 规范。

**优先级**：P1（随路线图 Phase 4/5 实现）

---

## C. 实施顺序建议

| 批次 | 范围 | 说明 |
| --- | --- | --- |
| 第 1 批（全局地基） | CSS token、--warm 修复、transition 收敛、reduced-motion 全局化、按钮/输入统一 | 一次改造全站受益，风险低 |
| 第 2 批（核心流程） | 首页、二级目录、预约填写页、我的订单 | P0 页面 |
| 第 3 批（后台主链路） | 运营工作台、需求处理、陪诊师管理 | P0 后台 |
| 第 4 批（体验打磨） | AI 咨询、用户中心、其余后台页 | P1/P2 |
| 第 5 批（未来扩展） | 数据统计、内容管理 | 随功能开发 |

每个页面验收必须对照 UI_DESIGN_SYSTEM.md 的规范逐项检查（颜色 token、44px 触控、间距、动效、reduced-motion、无硬编码色）。
