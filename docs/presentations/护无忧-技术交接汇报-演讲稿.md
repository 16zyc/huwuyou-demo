# 护无忧·智陪诊全链路平台技术交接汇报——演讲稿

## 第 1 页：封面

各位好，这次交接不只介绍页面功能，而是要让接手同事在一次汇报后完成四件事：能把系统跑起来、能按患者与管理员两条路径演示、能定位关键代码、能判断当前原型距离生产系统还有哪些差距。

## 第 2 页：系统边界

先给出最重要的判断：它是一个完整业务闭环的前端原型，不是已生产化的平台。患者端和后台共用 CareStore，并把状态保存到 localStorage，所以同一浏览器中可以切换角色演示数据联动。没有后端、数据库和真实鉴权，因此禁止录入真实患者信息。

## 第 3 页：功能全景

功能可以分为患者端、管理后台和跨端闭环三组。患者端负责提交、查询和查看结果；后台负责审批、派单、价格与报告；真正决定系统是否可靠的是跨端状态规则。当前没有独立陪诊师端，陪诊师只是后台可分配的资源对象。

## 第 4 页：启动与登录

这个项目没有 npm install 和构建步骤。进入目录后启动任意静态服务器即可。首页选择患者或管理员。患者验证码固定为 8888；管理员默认账号、密码和验证码都已经预填，也可以使用一键演示登录。业务数据会在刷新后保留，重置数据需要进入后台系统设置。

## 第 5 页：患者端

患者有两种入口：人工表单和 AI 助手。两条路径写入同一个需求草稿，切换不会丢失内容。AI 不是直接下单，它先解析字段，再依次进入确认、身份证、报告和最终提交阶段。提交后，患者在进度页查看管理员推进的状态；需求完成后才能看到报告。

## 第 6 页：管理端

管理端的核心演示是：患者提交后退出登录，进入管理员后台，在需求处理中分配陪诊师，然后在服务跟踪中推进到服务中和已完成。医院申请、收费和报告都有独立入口。最后回到患者端，可以看到通知、状态和报告同步变化。

## 第 7 页：业务闭环

这张图是最适合现场演示的主线。患者描述并确认资料后提交，后台收到通知并分配陪诊师，随后开始和完成服务。报告发布是独立动作，不会再次改变需求状态。所有动作都经 CareStore 写入，并通过角色通知把处理结果反馈给患者。

## 第 8 页：总体架构

当前是浏览器单体：界面层通过 DOM 字符串渲染，App、Patient、Admin 和 workflow 在同一个全局环境工作，领域状态集中在 CareStore，最底层依赖浏览器 localStorage、FileReader 和 Canvas。优点是部署简单；缺点是全局耦合明显，后续生产化必须拆分模块和接口。

## 第 9 页：代码结构

index.html 按 data、store、app、patient、admin、workflow 的顺序加载脚本。因为没有 ES Module，后加载脚本可以覆盖前面的对象方法。admin.js 代码量最大；workflow.js 只有约 190 行，却承担最新业务闭环的覆盖逻辑，因此修复问题时不能只看原始 app 或 admin 实现。

## 第 10 页：数据模型

Need 是中心实体。AI 和人工表单共用 Draft；陪诊师、医院申请、通知和报告都通过 ID 或明确字段与需求关联。Store 使用版本号 1 和固定键 huwuyou_store_v1。接手时新增字段要同步更新默认值、合并逻辑和渲染代码，否则旧浏览器数据会出现兼容问题。

## 第 11 页：需求状态机

需求只允许待处理到已分配、已分配到服务中、服务中到已完成。取消只能从待处理或已分配进入。界面会隐藏不允许的按钮，但真正的防线是 transitionNeed 中的 allowed map。发布报告不改变需求状态，只写入报告 ID 并发送通知。

## 第 12 页：AI 状态机

最新 AI 主流程不是黑盒对话，而是七阶段状态机。本地规则会识别医院别名、科室、日期、服务类型和辅助备注；缺什么就一次问一个问题。收集完成后仍然要经过详情确认、身份证、检查报告和最终确认。这样即使未来换成大模型，提交权限也应继续留在业务状态机。

## 第 13 页：医院申请与通知

未收录医院可以先进入草稿，但审批通过前不能提交需求。同一患者和医院的待审批申请会复用；驳回必须保留原因，并通过新申请重提。通知使用角色、类型、目标和事件键去重，患者和管理员只读取自己的通知。

## 第 14 页：持久化与媒体

Store 在加载时合并默认字段，JSON 损坏会备份原字符串并恢复演示数据。图片通过 FileReader 和 Canvas 压缩成 Data URL。需要特别说明：当前写入失败时会提示，但内存已经修改，并没有事务回滚。真实系统必须把图片放对象存储，把结构化数据放数据库，并在后端做校验。

## 第 15 页：部署

部署不需要编译产物，只需把静态文件同步到服务器目录。Nginx 配置将 huwuyou-demo 路径映射到 var/www 下的目录，并设置 index.html。上线演示前重点检查目录权限、尾斜杠跳转、浏览器缓存和敏感资料警示。

## 第 16 页：生产化差距

生产化不要从换 Vue 或 React 开始。第一优先级是隐私、鉴权、数据库和文件存储；第二步把业务能力封装为 API，并建立 AI/OCR 后端网关；最后才是工程化与可观测性。现有状态机和用户确认原则可以保留，页面实现可以逐步替换。

## 第 17 页：接手清单与结论

建议第一天只做运行和全链路演示；第二天按 Store、workflow、App 和页面的顺序读代码；第三天建立回归清单；之后再修复和补测试。交接是否成功，不看是否把所有代码读完，而看能否复现业务闭环、解释当前边界，并在修改状态规则时不破坏其他流程。
