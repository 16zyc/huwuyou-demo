# 当前 UI 分析

> 本文档基于对 `src/styles/style.css`、`src/styles/workflow.css` 及 `src/scripts/patient.js`、`src/scripts/admin.js`、`src/scripts/app.js` 的实际代码扫描得出。
> 所有结论均以代码为准，不采信任何文档的 UI 描述。
> 生成时间：2026-08-08

## 1. 整体视觉评价

当前项目是一套 **"患者端手机壳 + 管理后台双形态"** 的单页应用：

- 患者端以桌面浏览器中的手机壳（`#phone-frame`，max-width 420px、圆角 24px、投影）呈现，移动端全宽沉浸。
- 管理后台为 240px 侧边栏 + 60px 顶栏 + 内容区（max-width 1400px）的经典 SaaS 布局。
- 视觉语言为 **"医疗蓝 + 浅灰底 + 白色卡片 + 衬线标题"**：整体干净、可信，但存在细节粗糙、层级扁平、组件质感一般的问题。
- 页头标题使用衬线字体 `Noto Serif SC`（品牌特征），正文使用 `Noto Sans SC`，这是当前最鲜明的品牌基因，应保留。

总体评价：**骨架完整、风格统一、可信感达标；精致度与细节质量不足**，属于"能用的 SaaS 界面"而非"有设计感的医疗产品"。

### 2.2 已发现的配色 Bug

1. **`--warm` 未定义**：`.tag-orange { color: var(--warm); }`（style.css:202）引用了不存在的变量，导致该标签文字颜色回退为继承色（通常变黑）。应修复为 `var(--accent-amber)`，这是 bug 修复，不属于改品牌色。
2. **硬编码颜色泛滥**：style.css 中约有 77 处直接写死颜色（`rgba(196,146,46,0.08)`、`rgba(15,23,42,.55)`、`#fff` 等）。建议收敛为语义 token，但不改变色值本身。

### 2.3 判断结论

- **必须保留**：`#3b6cb5` 蓝（主）、`#2c5a9e` 深蓝、`#c4922e` 琥珀、slate 灰阶、Noto Serif SC 衬线标题。
- **可微调（不改色值，改用法）**：
  - 卡片从"1px 边框 + 极浅阴影"双层描边改为"以阴影为主、边框为辅"，减少生硬感。
  - `--text-muted` 仅用于占位符/禁用；新增 `--text-tertiary: #64748b` 作为可读的低强调文本。
  - 阴影改为"近距小影 + 远距柔影"双层（如 `0 1px 2px rgba(15,23,42,0.05), 0 4px 16px rgba(15,23,42,0.06)`）。

## 3. 字体体系

### 3.1 当前实现

- 全局：`'Noto Sans SC', -apple-system, "PingFang SC", "Microsoft YaHei", ...`，14px（style.css:34）。
- 标题：`h1-h4` 使用 `'Noto Serif SC', "PingFang SC", "Songti SC", serif`，字重 700（style.css:35）。
- 字号无 scale token，代码中手写 10/11/12/13/14/15/16/17/20px。

### 3.2 问题

1. **无字号阶梯**：各页面字号不统一，维护成本高、层级不稳定。
2. **衬线标题使用缺乏节制**：全站 h1-h4 一刀切衬线，页面里任何标题都变衬线，导致"医疗书籍感"过重、缺少现代感。建议衬线仅用于**页面主标题/品牌展示**，卡片与模块标题回归无衬线。
3. **正文 14px 偏小**：患者端移动场景建议正文 15px、辅助 13px；后台保持 14px 以提高信息密度。
4. 字重仅用 400/500/700，建议明确 500 用于控件文字、600 用于强强调。

## 4. 布局结构

### 4.1 患者端（手机壳）

- 桌面：`#phone-frame` max-width 420px、高度 `calc(100vh - 48px)`、圆角 24px、阴影 `0 8px 40px`（style.css:104-107）。
- 移动端：全宽、无壳。
- 底部 TabBar：56px（`--tabbar-h`）。
- 页面内边距：混用 12/14/16/18/24px，非 8pt 体系。

### 4.2 管理后台

- 侧边栏 240px（可折叠），顶栏 60px，内容区 padding 24px、max-width 1400px（style.css:517）。
- 后台页面均为"页头（标题+副标题）+ 统计卡片 + 表格/列表 + 弹窗"结构。
- 768px 以下：侧边栏转为抽屉，患者端手机壳消失。

### 4.3 问题

1. **间距非 8pt 体系**：8/12/14/16/18/24 混用，节奏不统一。
2. **卡片排列缺乏一致网格**：后台统计卡片、列表卡片间距各写各的。
3. **页面层级扁平**：页头与内容之间缺少明确层级区分；手机壳内无页面转场层级感。
4. **无 iPad 专项断点**：768px 从手机壳直接切后台布局，平板场景未考虑。

## 5. 组件系统

### 5.1 按钮（style.css:87-96）

- `.btn`：全宽、padding 10px 16px、圆角 8px、主蓝底白字、hover 变亮+阴影、active `scale(0.99)`、`transition: all .2s`。
- `.btn-outline`：透明底 + `--border-light` 描边。
- `.btn-sm`：12px 字、6px 12px 内边距。
- `.btn-link`：文字按钮。
- `.btn-danger`：红底。
- `.btn-login`：高 44px、字间距 4px。

评价：结构合理，但高度不统一（多数按钮高度约 38-40px，低于 44px 触控目标）；`transition: all` 应改为指定属性；active 反馈过弱。

### 5.2 输入框（style.css:74-76）

- `.fg-input`：padding 10px 12px、1px 边框、圆角 8px；focus 时主色边框 + `0 0 0 2px rgba(59,108,181,0.15)` 光环。
- 评价：**focus 光环已经是正确的现代做法**，值得保留并统一（建议 3px 更清晰）；缺少错误态（红框 + 辅助错误文案）与成功态。

### 5.3 卡片

- 普遍"1px 边框 + 极浅阴影"双层描边（`.card` 系），显得生硬。
- 状态徽章：8% 底色 + 20% 同色边框 + 4px 圆角（style.css:198-205），做法正确，可保留为统一规范。

### 5.4 弹窗 / 抽屉

- 弹窗 `.modal-box`：圆角 12px、max-width 720px（style.css:646）。
- 底部抽屉 `.workflow-sheet`：遮罩 opacity .18s + 面板 translateY .22s ease（workflow.css:61-64），**已是标准移动端动效**。

### 5.5 后台表格/统计

- 统计卡、表格、筛选条结构完整，但视觉密度与层级不足（阴影弱、无 hover 反馈、筛选条样式不统一）。

## 6. 动画系统

### 6.1 当前实现

- 唯一 keyframes：`fadeIn`（opacity + translateY 4px，.25s ease，style.css:118-119），用于页面重绘。
- transition 全部为 `all .15s/.2s`。
- 底部抽屉已有 mask fade + translateY。
- `prefers-reduced-motion: reduce` 兜底已存在（workflow.css:675），动画时长压到 .01ms——**这是加分项**。

### 6.2 问题

1. **无缓动 token**：所有动画用 `ease`，缺少 Apple 式"快进缓出"曲线。
2. **无页面转场体系**：只有 fade-in，没有层级的推入/返回动效。
3. **点击反馈不足**：按钮仅 scale(0.99)，列表/卡片无按压态。
4. **无加载态规范**：无骨架屏/加载指示器统一规范。
5. **transition: all 滥用**：应指定 `background-color/transform/box-shadow/opacity`，避免意外动画。

## 7. 交互体验

- 触控目标：部分按钮/标签低于 44×44pt（`.btn-sm`、`.tag`、图标按钮），移动端需要补足。
- `:focus-visible` outline 3px 已存在于 workflow.css（加分项），但 style.css 系页面未统一。
- 表单提交无防重复/成功反馈动效。
- 后台表格行无 hover/选中态规范。
- 手机壳内页面切换依赖 JS 重建 innerHTML + fade-in，无路由式转场。

---

## 8. 响应式表现

- 断点：1024px（后台两列统计折一列）、768px（手机壳/侧栏抽屉切换）、767px（移动布局）、374px（单列极窄）。
- 移动端：患者端全宽，底部 TabBar 含 `env(safe-area-inset-bottom)` 支持。
- 缺口：无平板专项布局；后台表格在窄屏无横向滚动规范；极窄屏字号未降级。
