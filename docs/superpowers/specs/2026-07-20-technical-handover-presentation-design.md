# 护无忧技术交接演示文稿设计

## 沟通目标

面向即将接手系统的技术人员，用一套可编辑 PowerPoint 在一次汇报中讲清楚：系统解决什么问题、如何操作、当前代码如何组织、关键状态和数据如何流转、原型技术边界在哪里，以及接手后的优先工作是什么。

## 事实边界与优先级

- 当前仓库代码是 As-Is 现状的最高优先级事实源；需求文档和设计文档仅用于解释目标与背景，未落地能力必须标注“规划中”。
- 当前交付是单页纯前端演示原型，不表述为已经生产化的 SaaS 后端。
- 业务数据通过版本化键 `huwuyou_store_v1` 保存在浏览器 `localStorage`。
- 最新 AI 填单主流程由本地规则解析和显式状态机驱动；旧代码中的 DeepSeek 调用视为遗留/可选路径，不作为当前安全架构承诺。
- 不虚构真实业务指标、并发能力、识别准确率或上线效果。
- 对实现与设计不一致的地方明确标注。例如当前 `CareStore` 在修改内存后调用 `save()`，存储失败不会自动回滚旧内存值，因此不能宣称已具备事务性回滚。

## 叙事结构

采用“理解系统 → 跑通系统 → 看懂实现 → 明确接手动作”的学习路径，共 17 页：

1. 封面与交接目标
2. 一张图认识系统边界
3. 角色与功能矩阵
4. 患者端使用路径
5. 管理端使用路径
6. 端到端业务闭环
7. 总体技术架构
8. 前端模块和加载关系
9. 核心数据模型
10. 需求状态机
11. AI 辅助填单状态机
12. 医院申请与通知闭环
13. 持久化、图片与异常恢复
14. 部署与运行方式
15. 安全和生产化差距
16. 接手顺序与验证清单
17. 结论与下一步

患者端和管理端操作页必须给出可直接照做的启动方式、访问路径、演示账号/验证码、关键点击顺序、跨角色处理闭环和“重置演示数据”入口，并配 2–4 张当前界面截图。

## 视觉系统

- 16:9，白底、深蓝黑正文、亮蓝强调、橙色风险提示。
- 从零构建独立的学术技术视觉系统：大标题、十二列网格、细分隔线和高留白，避免密集 UI 卡片风格，不混用任何现成模板路线。
- 简单且需要接手者后续编辑的关系使用 PowerPoint 原生形状；复杂拓扑才使用 Graphviz。关键图包括 C4 风格架构图、双泳道业务流、需求状态机、AI 状态机和数据关系图，且只展示代码已实现关系，不用虚构统计图充当证据。
- 正文字号不低于 16 pt，页标题不低于 35 pt；每页只承担一个技术结论。

## 演讲稿

每页附约 45–90 秒的讲解备注，说明本页结论、演示动作、技术实现和接手提醒；同时输出独立 Markdown 演讲文稿，便于复制、审阅和打印。

## 验证

- 导出后逐页渲染 PNG，检查溢出、遮挡、换行和连接线穿越。
- 运行幻灯片边界测试。
- 对照代码复核状态值、存储键、文件职责和部署方式。
- 技术底座必须明确：零构建原生 HTML/CSS/JavaScript、全局脚本加载顺序、DOM 字符串渲染与内联事件、`localStorage`、图片 Data URL 和 Nginx 静态目录；同时列明当前没有后端、数据库、真实鉴权、真实短信、生产 OCR/LLM、自动化测试和工程化构建链。
- 每张实现类幻灯片在页脚或备注标注对应代码文件，末页附事实来源与代码索引。
